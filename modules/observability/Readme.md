# Observability

This sections describes installed tools for monitoring running system.
We install a solution based upon the [prometheus operator](https://prometheus-operator.dev/), so the scripts defines the required CRD, installs the operators and a set of systems required to have a complete monitoring solution. A ``pushgateway`` is also installed for services that cannot be directly grabbed by prometheus (e.g. cronjobs).

https://github.com/kubernetes/kube-state-metrics/tree/master/docs#exposed-metrics

## Configuration.

To have a list of the available configurations  

```sh
helm show values prometheus-community/kube-prometheus-stack
```

> The file ``prom_complte.config`` in this folder is the output of the above comand.

We currently override some of the default configurations with the ``values_prom_grafana.template.yml`` file. 


## ServiceMonitor

In order to monitor a running service define a ServiceMonitor configuration, taking particular care to the ''release'' parameter, that is configured in the  ``Prometheus`` CRD and should match the release label in a ``ServiceMonitor`` configuration, as shown in the folowing example. 

```yaml
# ServiceMonitor
metadata:
  labels:
       release: observability
```

## Grafana

A complete grafana instance is provided.
Default dashboards are configured directly by the scripts.
The complete list of customized dashboards, with configured alerting, can be found [here](https://github.com/quandopasso/grafana).

Some grafana configs are overridden in values_prom_grafana_template. 

> Admin user is ``quandopasso_admin`` while the password is generated as a random sequence each installation. They can be found in the ``.grafana`` file generated by terraform upon installation.

Grafana helm chart documentation can be found [here](https://github.com/grafana/helm-charts/blob/main/charts/grafana/README.md)
